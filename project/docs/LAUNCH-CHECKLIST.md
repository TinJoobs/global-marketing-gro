# Launch Checklist

## Brand and content

- [ ] Approve the rebrand copy and the two-core-solution hierarchy.
- [ ] Confirm the $10/hour general VA starting rate and specialized-rate qualification.
- [ ] Confirm the primary business number and provide an approved email address.
- [ ] Verify leadership names/roles and the current location wording.
- [ ] Confirm permission to carry forward the public portfolio listings.
- [ ] Review the careers page and confirm whether applications should be accepted.
- [ ] Replace extracted mockup photos and the raster mark with approved originals when available.
- [ ] Replace Privacy, Terms, and Refund drafts with approved final policies.
- [ ] Change the policy pages' robots settings only after final approval.

## Forms, calendars, and workflows

- [ ] Add the real GHL consultation form using the documented fields.
- [ ] Map every native/custom field in the correct sub-account.
- [ ] Add the general strategy calendar and any specialized calendars.
- [ ] Confirm availability, calendar owner/team, and displayed time zone.
- [ ] Add a separate careers form and recruitment workflow if using the careers page.
- [ ] Remove every inactive preview notice from the production conversion pages.
- [ ] Test contact creation/update and duplicate handling.
- [ ] Test service-specific calendar routing and fallback behavior.
- [ ] Confirm inquiry notifications, appointment confirmations, and reminder workflows.
- [ ] Confirm email/SMS permissions, wording, and applicable communication requirements.
- [ ] Confirm cancellation and rescheduling behavior in GHL.
- [ ] Trigger the thank-you redirect only after an actual successful submission.
- [ ] Check widget heights, scroll behavior, fallback links, and mobile usability.
- [ ] Confirm privacy behavior before changing click-to-load or adding any tracker.
- [ ] Test attribution in GHL if campaign-parameter forwarding is enabled.
- [ ] Never place private API credentials in client-side HTML or JavaScript.

## Publishing and routing

- [ ] Choose the shared-asset, standalone, or GHL-block edition.
- [ ] Preserve the full folder structure for the shared-asset edition.
- [ ] Publish all target pages, not just the homepage.
- [ ] Match every route to the final domain and path format.
- [ ] Update canonical, Open Graph, and sitemap URLs to the final routes.
- [ ] In GHL, enter SEO fields in the page settings separately.
- [ ] Configure old-to-new redirects at the actual host; do not assume the static files create them.
- [ ] Configure the real 404 response and test an invalid URL.
- [ ] Confirm HTTPS and any host security headers or content-security policy.
- [ ] Allow the actual GHL iframe and helper-script domains in any content-security policy.
- [ ] Verify social-preview image availability at its final public URL.
- [ ] Check for duplicate default GHL headers, footers, margins, or page titles.

## Final published-site acceptance

- [ ] Test the published website in current Chrome, Safari, Firefox, and Edge.
- [ ] Test real phones and tablets, portrait and landscape.
- [ ] Check keyboard focus, dropdowns, menu closure, forms, and FAQ accordions.
- [ ] Test reduced motion and the pause-animations control.
- [ ] Review long text, large text settings, and keyboard-only usage.
- [ ] Check all public and external links on the final domain.
- [ ] Complete one real consultation submission, booking, and applicant submission as applicable.
- [ ] Confirm the right GHL records, workflows, notifications, and consent state.
- [ ] Review the site after disabling JavaScript; use direct slug links if needed for GHL.
- [ ] Save the approved launch version and retain a rollback copy.

The included QA report covers the delivered frontend and simulated integration hooks. It does not replace testing the actual hosting environment and connected GHL account.
